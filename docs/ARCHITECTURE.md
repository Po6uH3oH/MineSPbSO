# Решения

- TypeScript: Electron main отвечает за установку, файловые операции, защищённое хранение и запуск. Renderer без Node, только ограниченный preload API. Отдельный HTTP-сервис аккаунтов и PostgreSQL.
- Игровое имя ASCII `[A-Za-z0-9_]{3,16}`, уникальность по lower-case. Точное написание после создания неизменно. UUID = Java `UUID.nameUUIDFromBytes(UTF8("OfflinePlayer:" + exactName))`; отдельный случайный UUID аккаунта. Пароль/сессии не влияют на игровой UUID.
- NeoForge configuration task должен завершаться только после положительного ответа сервиса. Challenge создаёт сервер, билет выдаётся при фактическом подключении, а не при старте JVM. Проверка связана с профилем соединения. Refresh token остаётся в Electron.
- Offline Minecraft не шифрует соединение. Рабочая схема требует TLS gateway: launcher поднимает loopback TCP listener и соединяется с TLS endpoint, Minecraft server доступен только из loopback/private network. Проверка TLS сертификата обязательна. Без туннеля активный MITM может захватить уже подтверждённое соединение; одни билеты этого не исправляют.
- Фракции отложены по просьбе владельца; не требуются при регистрации или запуске. Существующая колонка базы оставлена для совместимости. Команды FTB автоматически не меняются.
- Выпуск модпака и лаунчер версионируются независимо. Доверенный Ed25519 public key встроен в конфигурацию лаунчера; приватный ключ только у издателя. Смена корня доверия требует доверенного обновления лаунчера.
- Пользовательские данные в постоянном game directory. Управляемые JAR переключаются как согласованный каталог только при остановленной игре; журнал восстановления обязателен. Конфигурации по умолчанию создаются только при отсутствии; принудительные конфиги выделяются явно.

## Локальный импорт 0.1.3

Владелец явно выбирает папку установленного профиля. Это доверие к локальным исполняемым модам, а не проверка подписи публичного выпуска. Копируются только mods/config/resourcepacks/datapacks/shaderpacks/options.txt; кроме mods все файлы имеют политику «создать при отсутствии». Миры и другие данные исходного профиля не копируются. Для копирования используется SHA-256 cache и существующий транзакционный updater.

Для стандартной структуры Modrinth `profiles/<профиль>` читается соседний `meta`. Импортируется ровно `1.21.1-21.1.256`, включая результаты processor из `version.data`: без patched client один BootstrapLauncher недостаточен. Библиотеки проверяются по SHA-1 там, где его предоставляет исходный metadata. Сгенерированные локальные файлы без опубликованного хеша доверены как часть выбранной установки; это не доказательство происхождения из Maven. Файлы installer-only не включаются в runtime classpath.

В локальном режиме Minecraft открывается в меню с offline UUID подтверждённого аккаунта, без билета или автоматического подключения. Если настроен подписанный серверный выпуск, локальный импорт не позволяет обойти его проверки. Рабочий серверный путь по-прежнему требует обязательный community-gate, подписанный манифест, TLS и проверку билета.

## Выбор ядра

XMCL: MIT, модульные TypeScript-пакеты, NeoForge installer и аргументы запуска, Windows/Linux/macOS. Старый minecraft-launcher-core-node архивирован 06.05.2026, разработка пакетов перенесена в монорепозиторий x-minecraft-launcher. Используем npm-пакеты, не форк приложения; версии фиксируются lockfile, фактические сигнатуры проверяются по установленным исходникам.

Helios: MIT, готовое Electron-приложение с установкой Java/Forge, обновлениями и Windows/macOS/Linux. Его аккаунтный сценарий ориентирован на Microsoft/Mojang, а точную поддержку требуемого NeoForge нужно дополнительно проверять. Форк потребовал бы замены существенной части аккаунтов/распространения, поэтому для данного проекта выбран XMCL.
