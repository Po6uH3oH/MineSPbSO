# Тест MineSPbSO 0.2.0 через Porthole

**Перед запуском** пройди [настройку защищённого сервера](PROTECTED-SERVER.md). На TCP 48905 принимает игровой TLS-шлюз, Minecraft слушает 127.0.0.1:48906.

## На компьютере владельца

1. Включи виртуальную сеть с IP `10.99.52.8`, Minecraft на приватном порту и его шлюз на TCP 48905 и BlueMap на TCP 8100. При проверке голосовой мод использовал UDP 24454.
2. Оставь работающим сервис аккаунтов на `127.0.0.1:3000`. Для запуска с Яндекс Почтой есть [инструкция SMTP](TEST-YANDEX.md).
3. Выпуск и ключи для этого ПК уже подготовлены. Из PowerShell в папке проекта запусти раздачу:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start-testers.ps1
   ```

4. Оставь окно открытым. Раздача слушает `https://10.99.52.8:3443`. Установщик доверяет приложенному публичному сертификату. В виртуальной сети должны быть доступны TCP 3443, 48905 и 8100. Сертификат тестовой сети действует год.
5. Передай тестеру **MineSPbSO-0.2.0-Setup.exe**. Закрытые ключи из `.local/tester-keys`, база аккаунтов и `.env.local` нужны только владельцу.

## На компьютере тестера

1. Подключись к виртуальной сети, установи лаунчер на Windows x64.
2. Вкладка «Разработчикам» принимает IP без порта. Введи `10.99.52.8`, сохрани и нажми **«Проверить подключение»**. Будут отдельно проверены аккаунты, подпись сборки, игровой сервер, карта и Maven. На компьютере владельца можно указать `localhost`.
3. В разделе «Аккаунт» зарегистрируйся, введи код из письма и войди. При наличии аккаунта достаточно войти.
4. Нажми «Играть». Новая установка скачивает сборку автоматически. Если раньше был выбран локальный профиль, нажми «Настройки → Загружать сборку с сервера». Индикатор показывает МБ текущего этапа. Лаунчер устанавливает собственную Java, Minecraft и NeoForge, затем подключается к серверу. На чистом ПК нужен доступ к источникам Java/Minecraft и Maven NeoForge.
5. Карта откроется в браузере. Онлайн запрашивается у Minecraft каждые 30 секунд. Для смены скина загрузи PNG, выбери модель и перезапусти игру. Оба игрока должны использовать настроенный CustomSkinLoader. Старый конфиг сохраняется в CustomSkinLoader.json.before-minespbso. Журнал мода находится в папке игры в CustomSkinLoader/CustomSkinLoader.log.

При ошибке выполни проверку на вкладке «Разработчикам» и экспортируй диагностику из настроек. Если отвечает игра, но недоступны аккаунты или сборка, проверь окно start-testers.ps1 и доступность TCP 3443. На чистой машине отказ Maven показывается до скачивания Minecraft. При установленном точном NeoForge допускается использование кеша Modrinth.

## Обновление сборки

Основная раздача берёт mods/*.jar, config, resourcepacks, datapacks, shaderpacks и options.txt. После изменений профиля запусти:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\prepare-testers.ps1
```

Для другой папки добавь `-Profile "D:\Папка сборки"`. Клиенты проверят подпись при следующем запуске и возьмут недостающие файлы. Изменённые игроком настройки сохраняются. Проверь разрешения авторов на распространение модов перед раздачей своей аудитории. [Аудит модов](MODS.md)

Для облака уже подготовлен ZIP в `.local/tester-distribution/LAYER-BETA-test.zip`. При изменении профиля можно создать новый ZIP командой `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\export-tester-zip.ps1 -OutputZip .local\pack-new.zip`. Загрузи разрешённые файлы на HTTPS-хостинг и передай скрипту подготовки путь к тому же ZIP и его прямую ссылку:

```powershell
.\scripts\prepare-testers.ps1 -Zip .local\tester-distribution\LAYER-BETA-test.zip -Url 'ПРЯМАЯ_HTTPS_ССЫЛКА'
```

Лаунчер проверяет размер и SHA-256 архива и файлов по подписанному выпуску. Для первого запуска подходит HTTPS-ссылка, возвращающая ZIP без входа, cookies или промежуточной HTML-страницы. Обычная ссылка просмотра Google Drive может потребовать подтверждение. При наличии только такой ссылки используй уже подготовленную раздачу через 3443. [Справка Google Drive](https://developers.google.com/workspace/drive/api/guides/manage-downloads)

## Выпуски тестерам

В приватном репозитории скачивай EXE из Releases с аккаунта, которому владелец предоставил доступ. Можно передать сам EXE. После отправки тега вида `tester-v0.2.0` GitHub Actions проверяет исходники, собирает NSIS и прикрепляет установщик и SHA-256 к предварительному выпуску. Для новой версии повысь version в package.json и отправь соответствующий тег. Тестовые установщики пока без подписи издателя Windows. Новую версию ставят поверх предыдущей.

Вход в мир требует действующего билета, подтверждённого аккаунта и присутствия в синхронизированном списке допуска.
