# Защищённый сервер MineSPbSO 0.2.0

Игрок входит в лаунчер один раз. После нажатия «Играть» клиент получает обязательный мод Community Gate вместе с лаунчером и подключается через TLS. Сервер создаёт одноразовый запрос для конкретного подключения. Только авторизованный лаунчер с подтверждённым аккаунтом, совпадающими точным ником и игровым UUID получает билет. Сервер сверяет и погашает его перед допуском в мир. Время жизни запроса — 60 секунд с начала подключения. Пароль и refresh token остаются в лаунчере.

## Переход с 0.1.5 на ПК владельца

Команды выполняются в PowerShell из E:\MinecraftLauncher. Для этой машины папка сервера — C:\Users\Robinson\Desktop\test_server. Используй версию проекта и выпуск **0.2.0**. Из Releases возьми community-gate-0.2.0.jar и положи в release в папке проекта (на машине разработки он уже подготовлен). В установщике игрока клиентская копия мода уже есть.

1. Предупреди играющих о перезапуске. В **консоли Minecraft** введи `stop` и дождись сохранения мира. Сохрани резервную копию мира, server.properties и whitelist.json.
2. Останови старые процессы **сервиса аккаунтов** и **раздачи сборки** в их окнах через Ctrl+C. Обнови их до кода 0.2.0. Запусти сервис аккаунтов привычной командой start-yandex.ps1 и введи почтовый пароль приложения в его запрос. Обновление схемы существующей базы выполняется при старте. Запусти обновлённый start-testers.ps1 во втором окне. Проверь здоровье сервиса на http://127.0.0.1:3000/health. Существующий подписанный модпак переиздавать не требуется. Команды для двух отдельных окон PowerShell:

   ```powershell
   Set-Location E:\MinecraftLauncher
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start-yandex.ps1 -Login (Read-Host 'Логин Яндекс Почты без @yandex.ru')
   ```

   ```powershell
   Set-Location E:\MinecraftLauncher
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start-testers.ps1
   ```
3. Однократно подготовь остановленный сервер:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\secure-server.ps1 configure "$env:USERPROFILE\Desktop\test_server"
   ```

   Скрипт ставит серверный JAR и меняет параметры на server-ip=127.0.0.1, server-port=48906, online-mode=false, enforce-secure-profile=false, white-list=true и enforce-whitelist=true. Остальные параметры сохраняются. Первая копия настроек хранится в server.properties.before-community-gate. Перед первой заменой существующего whitelist.json мод сохраняет whitelist.before-community-gate.json. При активном сервере на прежнем порту скрипт отказывается менять конфигурацию.
4. Для голосового чата в config/voicechat/voicechat-server.properties укажи `bind_address=10.99.52.8` и `voice_host=10.99.52.8:24454`, сохрани `port=24454`. Игра подключается к локальному TCP-туннелю, поэтому клиенту нужен явный внешний UDP-адрес. BlueMap по-прежнему использует 8100.
5. Запусти Minecraft со служебными параметрами в отдельном окне:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\secure-server.ps1 start "$env:USERPROFILE\Desktop\test_server"
   ```

   Для этого способа запуска нужны Java 21 и штатная установка NeoForge 21.1.256. Скрипт берёт ключ проверки из .env.local владельца и передаёт его серверной JVM. Во время следующих запусков используй этот скрипт вместо обычного run.bat.
6. Запусти игровой шлюз в отдельном окне:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\start-game-gateway.ps1
   ```

   Порты для Porthole: **48905/TCP** для защищённого игрового входа, **3443/TCP** для лаунчера, **8100/TCP** для карты и **24454/UDP** для голоса. Приватный backend 48906 слушает только loopback. Не пересылай этот порт через Porthole.
7. Тестеру передай **MineSPbSO-0.2.0-Setup.exe**. После установки поверх прежнего лаунчера нужно зайти с подтверждённой почтой, выбрать IP 10.99.52.8 и нажать «Играть». После регистрации или разблокировки вайт-лист обновится в течение 200 серверных тиков (около 10 секунд при 20 TPS). Работающий клиент 0.1.5 нужно обновить.

## Вайт-лист и проверка

- Владелец списка — база аккаунтов. В whitelist.json записываются только пары ник/игровой UUID для подтверждённых незаблокированных аккаунтов. Ручные добавления будут заменены. Операторы также проходят проверку сессии.
- Блокировка исключает игрока из списка и отключает активного персонажа при следующей успешной синхронизации. При временном отказе API новые входы отклоняются, существующий мир продолжает работать. Ошибка синхронизации не должна обнулять сохранённый список.
- Проверь правильный вход. Пока игрок находится в мире, попробуй подключиться под его ником другим клиентом. Настоящий игрок должен остаться в мире. Затем проверь тот же ник после выхода владельца — без сессии входа не будет. Копии модпака, JAR лаунчера и знания адреса недостаточно.
- Свободная регистрация остаётся открытой. Человек с собственной подтверждённой почтой получает доступ под своим ником. Для сообщества строго по приглашениям нужна отдельная политика одобрения.
- Если нужен откат, останови Minecraft и игровой шлюз, восстанови резервные копии server.properties и whitelist.json и убери community-gate из mods. Такой откат возвращает прежнюю возможность подмены ника. Для обслуживания безопаснее оставить игровой вход остановленным.

## Размещение на VDS и отдельной машине Minecraft

Сервис аккаунтов и PostgreSQL размещаются на узле A. Снаружи игрокам нужен HTTPS к API. Размести серверные маршруты POST /server/whitelist, /server/challenge и /server/consume за TLS для узла B. Они требуют SERVER_KEY; для удалённого размещения дополнительно ограничь доступ адресом B или приватной сетью. Публичный клиентский маршрут POST /join/ticket требует сессию игрока. Базу данных открывать на B не нужно.

На узле B работают Minecraft и TCP/TLS-шлюз. Шлюз всегда пересылает поток в **127.0.0.1 того же узла B**. На сервере включены white-list и enforce-whitelist. Установи JAR из того же выпуска. Задай переменные окружения JVM `SMP_API_URL=https://<домен-API>` и `SMP_SERVER_KEY` с тем же значением, что у сервиса. Для Linux можно запустить обычный run.sh в этом окружении. Java проверяет сертификат удалённого API по своему доверенному хранилищу. Используй действительный сертификат домена либо установи свой CA в выделенное серверное truststore.

На B настрой TLS_CERT, TLS_KEY, GATEWAY_HOST, GATEWAY_PORT (48905) и MINECRAFT_PORT (48906) и запусти `pnpm exec tsx src/service/gateway.ts` под менеджером служб. Сертификат игрового шлюза должен соответствовать адресу подключения игроков. При переносе API/сборки или смене корня доверия выпусти лаунчер с корректными apiUrl, gatewayHost, gatewayPort, gatewayCA, manifestUrl и manifestPublicKey. В рабочем режиме testerMode=false, проверка подписи манифеста и сертификата обязательна. Ключ подписи, ключ TLS и SERVER_KEY нужны только владельцу соответствующей службы.
