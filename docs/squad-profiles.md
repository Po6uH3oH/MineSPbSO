# Название студенческого отряда

В разделе «Аккаунт» пользователь вводит свободное название, например `ССервО Панда`. Пустая строка убирает тег. Допускается до 32 UTF-16 символов после NFC-нормализации и сжатия пробелов; коды форматирования, управляющие и невидимые символы, квадратные скобки, угловые скобки и обратная косая черта запрещены.

`POST /me/profile` принимает только `{ "squadName": "ССервО Панда" }`. Сервис требует действующую сессию, подтверждённую почту и допуск. UUID берётся из сессии; роль, клан и UUID в теле запроса не принимаются. Название — заявление самого игрока, а не подтверждение членства в реальном отряде.

Миграция добавляет `accounts.squad_name` с пустым значением для существующих аккаунтов. `/me`, ответ входа и `/server/consume` возвращают `squadName`. Community Gate переносит название из успешно проверенного ответа в persistentData игрока:

- `minespbso_profile_verified`: boolean;
- `minespbso_squad_name`: string.

Данные привязаны к конкретному подключению и копируются при возрождении. При новом входе старые поля очищаются. Обновление отряда применяется при переподключении; отдельного сетевого канала для изменения роли нет.

Для отображения используйте `kubejs/server_scripts/layer_profiles.js` и `kubejs/config/layer_profiles.json` из пакета настройки LAYER. Скрипт сохраняет оформление Warring Nations, добавляя роль и отряд в серверное отображение имени и Tab. Роли назначаются администратором через `/layer_profile set_role <player> <id>`. Теги над головами на удалённых клиентах этим скриптом не синхронизируются.

Порядок обновления: резервная копия базы → обновление сервиса и миграция → сборка и установка Community Gate на сервер и клиент → скрипты LAYER → обновление лаунчера. Старый сервис совместим с новым Gate: отсутствующее название становится пустым. Изменения не требуют смены игровых UUID. Сохраняйте защищённую схему существующего проекта: Minecraft `server-ip=127.0.0.1`, `online-mode=false`, внешний вход через TLS gateway и обязательный Gate. Не выставляйте offline-порт Minecraft в интернет.

Проверено локально: разбор TypeScript, тест нормализации, компиляция Java против установленного NeoForge 21.1.256 и Java 21 API, модульные проверки KubeJS с подменой игровых объектов. Полные `pnpm check`, SQL/API-тесты, Gradle-сборка, UI и подключение двух игроков требуют CI/стенда: зависимости проекта локально не установлены.
